# Windows Extended PID (EPID) Format Guide

The **Extended Product ID (EPID)** is an alphanumeric string generated by the Windows software licensing service (and diagnostic tools like `pidgenx`). It is **not** a product key itself, but rather a structured metadata string that describes the exact attributes of a Windows license.

When you run a command like `slmgr /dlv` or use checking tools, the EPID is displayed to help administrators identify the exact channel, origin, and batch of the license.

---

## Standard EPID Structure

A standard Extended PID consists of 8 distinct sections separated by dashes, typically looking like this:

> **`AAAAA-BBBBB-CCC-DDDDDD-EE-FFFF-GGGGG.0000-HHHHHHH`**

Using your example EPID (`XXXXX-03307-137-617516-02-1033-26200.0000-2222026`), here is how to read each section:

### 1. `AAAAA` (OS Family / Application ID)
*   **Example:** `XXXXX`, `03612`, `55041`
*   **Meaning:** A 5-digit code identifying the overarching Operating System family, application, or Product Key Group. This maps directly to the Application GUID in the Microsoft Software Protection Platform (SPP).

**Full Known OS ID List:**
*   **`03612`**: Windows 10 & 11 Client (Retail/OEM/MAK) **AND** Microsoft Office 2016, 2019, 2021
*   **`55041`**: KMS Host Server (Identifies that the EPID was generated by a Key Management Service host, not a local client)
*   **`59146`**: Microsoft Office 2010
*   **`06401`**: Microsoft Office 2013
*(Note: Older OS versions like Windows XP used a different licensing mechanism, so they do not use this standard modern EPID format).*

> [!NOTE]
> **Why do I see `XXXXX` in WinLic?** When you use third-party or offline key checking tools (like `WinLic` or `ShowKeyPlus`), these programs call the internal `PidGenX` Windows API directly. The `PidGenX` function requires an `MPC` (Microsoft Product Code) parameter to generate the EPID string. Because offline checkers don't always know the exact OS ID for every key ahead of time, developers often pass a generic placeholder string into the API. The `PidGenX` DLL does not actually validate this string—it blindly prepends it to the final EPID output! `WinLic` explicitly uses `"XXXXX"` as its default placeholder so it is instantly obvious to the user that the OS ID portion of the EPID is a placeholder and not a genuine Microsoft OS ID.

### 2. `BBBBB-CCC-DDDDDD` (Product Key ID / Serial Number)
*   **Example:** `03307-137-617516`
*   **Meaning:** This 14-digit block (`BBBBBCCCDDDDDD`) is the **Unique Serial Number** (or Key ID) of your specific product key.
    *   **`BBBBB`**: Often refers to the Branch Product Code (BPC) or specific Key Group ID.
    *   **`CCC-DDDDDD`**: The sequential serial identifier within that group.
*   > [!TIP]
    > **Physical Verification:** If you have a physical retail or OEM package, removing the dashes from this section (e.g., `03307137617516`) will perfectly match the 14-digit **COA Barcode** printed on your physical Microsoft sticker.

### 3. `EE` (License Channel)
*   **Example:** `02`
*   **Meaning:** A 2-digit code indicating how the license is distributed (the Activation Channel). Common codes include:
    *   `00` or `01`: Retail (Full Packaged Product)
    *   `02`: OEM (Original Equipment Manufacturer)
    *   `03`: Volume Licensing (KMS - Key Management Service)
    *   `04`: Volume Licensing (MAK - Multiple Activation Key)
    *   `06`: OEM SLP (System Locked Pre-installation)

### 4. `FFFF` (Language Code / LCID)
*   **Example:** `1033`
*   **Meaning:** The standard Microsoft Locale ID (LCID) of the system where the EPID was generated or validated.
    *   `1033`: English (United States)
    *   `1049`: Russian
    *   `1066`: Vietnamese
    *   `0000`: Language Neutral (often seen in KMS environments)

### 5. `GGGGG.0000` (OS Build Number)
*   **Example:** `26200.0000`
*   **Meaning:** Identifies the exact Windows Build Number of the host operating system that processed the key or generated the EPID. For example, `19045.0000` means it was checked on Windows 10 22H2, while `26200.0000` indicates a recent Windows 11 Insider/Server build.

### 6. `HHHHHHH` (Julian Date)
*   **Example:** `2222026`
*   **Meaning:** A 7-digit date code indicating exactly when this EPID was generated, validated, or when the license request was made. It uses a specialized Julian date format representing the year and the day of the year.

## Summary Example Breakdown

If we decode your EPID **`XXXXX-03307-137-617516-02-1033-26200.0000-2222026`**:

| Section | Value | Interpretation |
| :--- | :--- | :--- |
| **OS ID** | `XXXXX` | (Placeholder injected by WinLic offline tool) |
| **Serial / COA** | `03307-137-617516` | Key ID matches physical barcode `03307137617516`. |
| **Channel** | `02` | This is an **OEM** license. |
| **Language** | `1033` | Validated in an **English (US)** environment. |
| **OS Build** | `26200.0000` | Checked using OS build **26200**. |
| **Date Code** | `2222026` | Julian timestamp of when the check/generation occurred. |

> [!NOTE]
> Because the EPID includes environment-specific data (like the Build Number, Language Code, and current Date), **the exact same Product Key will generate a slightly different EPID** if you check it on a different computer, in a different language, or on a different day! However, the core Serial Number (`BBBBB-CCC-DDDDDD`) will always remain identical.
